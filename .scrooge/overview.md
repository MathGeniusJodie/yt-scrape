**yt-gtk** is a GTK3 desktop application that lets users browse YouTube channel feeds, play videos via mpv, view transcripts, generate AI summaries, and manage a watch-later list — all from a local GUI.

The architecture centers on an `AppState` that owns all video data in memory as an `IndexMap<String, Video>`, tracking separate ID lists for the feed, search results, and a watch-later `HashSet`. A filesystem-backed `Storage` layer persists a `videos.json` index plus per-video JSON sidecars for transcripts, AI summaries, and watched state — this split avoids bloating the main index while keeping metadata queryable. Feed data flows through `feed/fetcher.rs`, which hits the YouTube Data API v3 (playlists, channels, search) with exponential backoff, concurrency caps, and per-channel retry logic; a progress channel streams `FetchProgress` events so the UI shows granular status. The UI runs on the GTK main loop but bridges to tokio via a dedicated `Runtime`, communicating state changes through `glib::idle_add` so widgets are only mutated on the main thread. Summaries use a two-tier provider strategy via a `SummaryGenerator` service: Gemini Flash is tried first (with URL-context tooling), then OpenRouter with the fetched transcript as fallback, then raw transcript as a last resort — all three paths emit `StreamingMessage` chunks over an async channel so the UI can progressively render output. Downloaded videos and thumbnails live in well-known subdirectories under the platform cache directory, and the `cache` module spawns external processes (yt-dlp, ffmpeg) under `nice -n 19` to avoid starving the UI. A "frogpoints" gamification layer gates feed refreshes (debiting 10 points each) and charges leisure time (1 point per minute of mpv playback when no recent SVG edits are detected), with all URL construction centralized in `urls.rs`.
